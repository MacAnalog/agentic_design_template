# Sign-off — the design of record

KIND: REFERENCE (what a reader is entitled to trust. `experiments/` is where these numbers came
from; this tree is what survived.)

**One rule decides whether a file belongs here: has it been measured, and does it say under what.**
An artefact reaches this tree when a bench produced it and someone wrote down the conditions.
Everything still being explored stays in `experiments/NNN-*/`.

## What is signed off

Fill one row per fidelity you have actually run. `status` is `certified` only when a signed ledger
row exists for it (`make certify ARGS="--author X --verified-by Y"`); anything else is `measured`,
`in progress` or `planned`.

| fidelity | what the number includes | scorecard | status | signed by | date |
|---|---|---|---|---|---|
| `prelayout` | schematic netlist; no interconnect parasitics | `prelayout/decks/scorecard.json` | — | — | — |
| `postlayout-pex` | + R/C extracted from the layout of record | `postlayout-pex/decks/scorecard.json` | planned | — | — |
| `postlayout-em` | + EM-solved interconnect and passives | `postlayout-em/decks/scorecard.json` | planned | — | — |

A design that never draws a layout keeps only the first row and deletes the other two directories.

## The tree

| path | holds | written by |
|---|---|---|
| `schematic/` | the topology of record: the as-built subckt netlist, its xschem sheet, the sizing table | `schematic-of-record` skill |
| `layout/` | the layout of record: GDS, render, DRC and LVS reports | `layout/signoff.py` (the generator is code, and stays in `layout/`) |
| `<fidelity>/decks/` | the frozen bench decks, sha-locked by `make freeze` | `make certify` |
| `<fidelity>/decks/scorecard.json` | every spec key, its measured value and its verdict — written INSIDE the frozen dir, because that is where `--certify` writes it | `make certify` |
| `<fidelity>/figs/` | the figures that carry the claims, each regenerated by a committed script | `plot.py` / the fidelity's own script |
| `<fidelity>/tables/` | the same numbers as CSV, so a later run can diff them | `make certify`, experiment close-out |
| `<fidelity>/REPORT.md` | what was measured, under what conditions, and what it means | the person or agent closing that fidelity |

## Adding a fidelity

The three shipped directories are simulation fidelities of an electrical design. A design in
another physics domain adds its own directory beside them — TCAD drift-diffusion for a device
cross-section, 3-D FDTD for an optical structure — with the same contents (`decks/`, holding its
`scorecard.json`; `figs/`; `tables/`; `REPORT.md`) and a row in the table above.

**Two things make a new fidelity real rather than a folder:** a `REPORT.md` that states the solver
and its version, and a `scorecard.json` written by the same `metrics` code path as every other
fidelity. A number produced by a one-off script is a report, not a reference.

## What does NOT belong here

**A yardstick is not a sign-off.** A design often carries a second certified deck set — prior art,
a paper being replicated, the incumbent being beaten. It is frozen, it is sha-locked, it is
reproduced by `make check`, and it is still not this design's result. It stays in `decks/`.

The distinction is worth stating because the config key does not make it: `reference_scorecard`
means *the scorecard `make check` reproduces*, which a design may legitimately point at the
yardstick rather than at itself. So the key cannot tell you which directory is the design of
record — only the design's own docs can.

| directory | holds | goes in `signoff/`? |
|---|---|---|
| this design's certified benches | what this design achieved | **yes** — `signoff/<fidelity>/decks/` |
| the prior-art / replication baseline | what it is measured against | no — `decks/`, still frozen |

If both exist, say which is which in the table above, and give the yardstick a row in the design's
`doc/target-spec.md` instead.

## Wiring it to the harness

Three lines in `harness.yaml` point the machinery at this tree. Nothing else needs to change:

```yaml
frozen: [signoff/prelayout/decks]                       # sha-locked by `make freeze`
reference_scorecard: signoff/prelayout/decks/scorecard.json   # what `make check` reproduces
```

**A design that certified before 2.00 can move its frozen directory here** — `make
template-migrate ARGS="--design-of-record decks/<dir>"` does it, and `make freeze` afterwards.

The one thing to know: a scorecard's `provenance` block records `script` and `raw` as
repo-relative paths, each beside a sha of that file's **contents**. A path pointing inside the
directory stops resolving when it moves, and `scorecard-recompute` says so. The migration repoints
exactly those keys, which keeps every hash valid — no byte of the rawfile, the scorer or any
number changes, so it is a relocation record and not a re-measurement.

**What does not move: a yardstick, a control, or a withdrawn row.** They are frozen too, and they
are not this design's results. They stay in `decks/` and get a role row in the table above.

`make check` compares today's simulation against `reference_scorecard`, so it follows whichever
fidelity that line names. Promoting post-layout to the reference is a deliberate act: change the
line, re-certify, and say so in this README's table.
